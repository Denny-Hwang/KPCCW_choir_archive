# 성가대 아카이브

Google Sheets를 DB로, GitHub Pages를 호스팅으로 쓰는 성가대 곡 아카이브 / 연습 링크 공유 앱.
서버 비용 0.

```
Google Sheets (7 데이터 시트 + N개 연도 뷰 탭)
      │  Apps Script 웹앱 (doGet → JSON, 읽기 전용)
      ▼
  단일 JSON 엔드포인트
      │  fetch + localStorage 캐시 (stale-while-revalidate)
      ▼
GitHub Pages (React SPA, 정적)
```

## 이 앱이 하는 일

| 화면 | 하는 일 |
|---|---|
| **홈** | 다가오는 찬양일, 파트 버튼 6개, **공지 복사** 한 번으로 카톡에 붙여넣기 |
| **아카이브** | 월별로 접히는 기록. 곡, 파트별 인원, 세션, 기록영상 |
| **곡** | 성가곡 pool 검색 + 악보집·절기·상태·난이도·검증 필터 |
| **서가** | 표지색 책등으로 보는 보유 악보집. 미보유 권은 빈 슬롯 |
| **선곡** | 월간 선곡. **중복 선곡 방지**가 핵심. 공지와 시트 붙여넣기 블록을 함께 생성 |
| **설정** | 시트 주소 연결, 데이터 점검 (미검증 링크·깨진 주소) |

## 설계상 지켜지는 것

- **일상 편집은 구글 시트에서 한다.** 앱은 읽기만 한다. 편집자가 5명 이내이고 모두 시트에
  익숙하므로, 인증·권한·쓰기 실패 처리를 상시로 떠안지 않는다.
- **열 위치가 아니라 헤더 이름으로 파싱한다.** 5명이 동시에 만지면 열 삽입·삭제가 반드시 일어난다.
- **자동 수집한 데이터는 초안이지 사실이 아니다.** `검증` 플래그를 통과해야 대원에게 노출된다.
  미검증 링크는 **공지 텍스트에서 제외**된다.
- **오프라인 내성.** 마지막 응답을 localStorage에 캐시하고, 네트워크 실패 시 캐시를 보여준다.

## 처음 설치하기

### 1. 스프레드시트 준비

1. 새 구글 스프레드시트를 만든다. 파일 > 설정에서 **시간대를 (GMT-07:00) 로스앤젤레스**로 맞춘다.
   시트 시간대와 `config`의 `시간대` 값이 어긋나면 날짜가 하루 밀릴 수 있다.
2. 확장 프로그램 > Apps Script를 열고, `apps-script/` 의 세 파일을 그대로 붙여넣는다.
   - `Code.gs` — JSON 엔드포인트
   - `Setup.gs` — 시트 생성·드롭다운·수식
   - `YouTubeSync.gs` — 채널 미러링·매칭·악보집 등록
3. 스프레드시트를 새로고침하면 상단에 **성가 아카이브** 메뉴가 생긴다.
4. **성가 아카이브 > 시트 초기 생성**을 실행한다.
   헤더 7장, 드롭다운, 곡코드 자동 생성 수식, config 기본값이 한 번에 들어간다.

### 2. 웹앱 배포

Apps Script 편집기에서 **배포 > 새 배포 > 웹 앱**:

| 항목 | 값 |
|---|---|
| 실행 주체 | **나** |
| 액세스 권한 | **모든 사용자** |

시트 자체는 비공개로 유지된다. 대원들은 로그인 없이 앱을 연다.
발급된 `.../exec` URL을 복사한다.

> 스크립트를 고칠 때마다 **새 버전으로 다시 배포**해야 반영된다. URL은 그대로 유지된다.

### 3. 앱 배포

1. 저장소 Settings > General > Default branch가 **`main`인지 확인한다.**
2. Settings > Pages > Source를 **GitHub Actions**로 바꾼다.
3. Settings > Secrets and variables > Actions > Variables에 `VITE_API_URL`을 위 URL로 추가한다.
   (건너뛰어도 된다 — 앱의 설정 화면에서 각자 넣을 수 있다.)
4. `main`에 푸시하면 배포된다.

> **deploy 잡이 스텝 없이 1초 만에 실패하고 로그도 비어 있다면**, 잡이 시작조차
> 못 한 것이다. 코드가 아니라 저장소 설정 문제이고, 웹 UI의 잡 화면 상단 주석에만
> 실제 사유가 뜬다 (API 로그는 404다). 확인 순서:
>
> 1. Settings > Pages > Source가 **GitHub Actions**인가
> 2. Settings > Environments > `github-pages`의 deployment branch 정책이 `main`을 허용하는가
>    — 환경이 처음 만들어질 때의 브랜치 이름이 그대로 박혀 있을 수 있다
> 3. 그 환경에 required reviewers가 걸려 있지 않은가

### 4. 데이터 넣기

곡 pool 300곡을 채우는 것은 앱 가동의 전제 조건이 **아니다.** 이 순서를 권한다:

1. `books`에 보유 악보집만 먼저 — 이것만으로 앱이 동작한다.
2. **`services`에 최근 1~2년 찬양 기록** — 선곡 화면의 중복 경고가 여기서 나온다.
   기록이 없으면 핵심 가치가 몇 달간 비어 있다. 곡 pool보다 이게 먼저다.
3. 곡은 선곡할 때마다 한 곡씩 추가해도 된다. pool은 시간이 지나며 채워진다.

## 유튜브 채널 미러링 (선택)

중앙아트TV 공식 채널에서 파트 영상과 수록곡 목록을 끌어온다.

1. [Google Cloud Console](https://console.cloud.google.com/)에서 YouTube Data API v3 키를 만든다.
2. Apps Script 편집기 > 프로젝트 설정 > 스크립트 속성에 `YOUTUBE_API_KEY`로 저장한다.
   서버측이라 프론트엔드에 노출되지 않는다.
3. **성가 아카이브 > 채널 동기화** — 채널 전체를 `yt_cache` 시트에 미러링한다.
4. `yt_cache`를 열어 **영상 제목 형식을 눈으로 확인한다.**
5. 필요하면 `YouTubeSync.gs`의 `parseVideoTitle_` 규칙을 고치고
   **성가 아카이브 > 영상 매칭**을 다시 실행한다.

> 4~5단계가 이 설계의 요점이다. 곡별 검색(`search.list`)은 호출당 100 units지만
> `playlistItems.list`는 50개당 1 unit이라, 채널 전체를 훑어도 수십 units에 그친다.
> 캐시가 시트에 있으므로 **매칭 규칙을 틀려도 할당량 없이 다시 돌릴 수 있다.**
> 실제 제목 형식은 한 번 받아보기 전에는 확정할 수 없다.

매칭된 링크는 전부 `검증 = FALSE`로 들어가고, 사람이 재생을 확인해 체크하기 전까지
**공지에 나가지 않는다.** 실패 목록은 `_매칭실패` 시트에 남는다.

## 공지 텍스트

기존 메모 포맷을 글자 단위로 재현한다. 대원들이 포맷 변화를 느끼면 안 된다.

```
8월 23일 주일 찬양
<성가연습 일정>
9일 주일 1시 30분
16일 주일 1시 30분
19일 수요일 8시
(합창)
https://youtu.be/vk1nDmhdy2w
(소프라노)
https://youtu.be/9yT6gnaWd6s
```

곡이 2개 이상이면 `1. 곡명` 헤더가 **자동으로** 붙는다. `config` 설정이 아니라 파생값이다 —
곡명 없이 링크 세트가 여러 벌 나오면 어느 것이 어느 곡인지 알 수 없기 때문에,
총무가 매번 판단할 문제가 아니다.

포맷은 `config` 시트에서 바꾼다. 코드를 건드릴 필요가 없다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `공지_제목형식` | `{M}월 {D}일 주일 찬양` | `{YYYY}` `{M}` `{D}` `{구분}` 치환 |
| `공지_연습헤더` | `<성가연습 일정>` | |
| `공지_곡목표시` | `FALSE` | 1곡일 때 제목 아래 곡명 한 줄 |
| `공지_빈줄구분` | `FALSE` | 구역 사이 빈 줄. 기본은 기존 메모 그대로 |
| `공지_파트순서` | `합창,소프라노,알토,테너,베이스,반주` | 출력 순서 |
| `중복경고개월` | `12` | 선곡 화면의 붉은 배지 기준 |
| `연습기본패턴` | `주일 13:30, 수요일 20:00` | 선곡 시 연습일 자동 제안 |
| `절기힌트` | `1:일반, 3:사순, ...` | 월 → 절기 제안 |
| `시간대` | `America/Los_Angeles` | 날짜·시각 해석 기준. 시트 설정과 같게 맞출 것 |
| `데이터시트목록` | `books,songs,...` | JSON으로 내보낼 시트. 연도 뷰 탭은 제외된다 |

## 개발

```bash
npm install
npm run dev      # 개발 서버
npm test         # 66개 테스트 (공지 포맷·URL 정규화·중복 판정)
npm run lint     # 타입 검사
npm run build    # 프로덕션 빌드
```

엔드포인트를 연결하지 않으면 `public/demo-data.json`의 예시 데이터로 동작하므로,
시트 없이도 모든 화면을 볼 수 있다.

### 코드 구조

```
src/lib/
  types.ts      도메인 모델
  schema.ts     한글 헤더 JSON → 모델 변환 (모든 실패는 빈 값으로 떨어진다)
  notice.ts     공지 텍스트 생성 — 포맷 회귀를 테스트로 잠가 둠
  planner.ts    월간 선곡, 중복 판정, 필터
  paste.ts      시트 붙여넣기 블록
  derive.ts     시트를 가로지르는 조회 (부른 이력, 파트별 링크)
  youtube.ts    URL 정규화
  api.ts        fetch + localStorage stale-while-revalidate
```

`notice.ts`의 출력은 테스트로 고정되어 있다. 포맷을 "개선"하는 변경은 전부 회귀다 —
바꾸려면 `config`를 통해야 한다.
