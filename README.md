# 중부워싱턴한인장로교회 성가대 아카이브

> **[앱 열기 →](https://denny-hwang.github.io/KPCCW_choir_archive/)**

[중부워싱턴한인장로교회(KPCCW)](https://www.kpccw.org/) 성가대가 언제 무슨 곡을 불렀는지 모아 두고,
파트별 연습 영상을 곡 단위로 묶어 보관하는 곳입니다.

카톡 링크로 열면 바로 보입니다. 로그인도, 앱 설치도 필요 없습니다.

---

## 대원용 — 이것만 알면 됩니다

앱을 열면 **홈**에 다가오는 찬양일이 나옵니다. 다음 찬양이 아직 정해지지 않았으면
가장 최근 찬양이 대신 보입니다.

- **파트 버튼**을 누르면 내 파트 연습 영상이 유튜브로 열립니다.
- 연습 일정이 그 아래 있습니다. 지난 연습은 줄이 그어지고, **다음 연습**에 표시가 붙습니다.
- **찬양기록**(그 날 우리가 부른 찬양 영상)은 버튼을 누르면 바로 열립니다. 없는 날은 교회 홈페이지 영상 게시판으로 갑니다.
- 내 파트 영상이 아직 없으면 점선 칸의 **유튜브에서 찾기**를 누르세요. 앱에 없어도 유튜브에는 있는 경우가 많습니다.

지난 곡이 궁금하면 **아카이브** 탭에서 월별로 펼쳐 보면 됩니다. 그 날 부른 곡과
파트 영상 링크가 함께 있고, 찬양기록 영상이 있는 날은 붉은 `찬양기록` 버튼이 붙습니다.
홈의 `지난 찬양` 목록에서 한 줄을 누르면 그 달 아카이브로 바로 갑니다.

> 카톡에서 링크를 열면 인앱 브라우저로 뜹니다. 유튜브 앱으로 바로 열고 싶으면
> 오른쪽 위 메뉴에서 `다른 브라우저로 열기`를 쓰면 편합니다.

### 홈 화면에 두고 쓰기

앱처럼 아이콘 하나로 여닫을 수 있습니다. 주소창 없이 전체 화면으로 뜹니다.

- **아이폰** — 사파리에서 열고 `공유` → `홈 화면에 추가`
- **안드로이드** — 크롬에서 열고 `⋮` → `홈 화면에 추가`

한 번 열어 본 뒤에는 인터넷이 느리거나 끊겨도 **마지막으로 본 내용이 바로 뜹니다.**
새 내용은 뒤에서 받아 조용히 바뀝니다.

## 총무·지휘자용

### 주간 공지 만들기

홈 화면의 **`공지 복사`** 버튼 하나면 됩니다. 지금까지 손으로 쓰던 것과 **글자 하나까지 같은**
텍스트가 클립보드에 들어갑니다. 카톡에 그대로 붙여넣으면 끝입니다.

```
8월 23일 주일 찬양

<성가연습 일정>
9일 주일 1시 30분
16일 주일 1시 30분
19일 수요일 8시

(합창)
https://youtu.be/vk1nDmhdy2w

(소프라노)
https://youtu.be/9yT6gnaWd6s
```

곡이 2개 이상인 날(성탄절 등)은 `1. 곡명` 헤더가 **자동으로** 붙습니다. 곡명 없이 링크만
여러 벌 나오면 어느 것이 어느 곡인지 알 수 없기 때문에, 따로 설정할 일이 아니라 자동입니다.

복사가 안 되는 브라우저(아이폰 사파리 등)에서는 `텍스트 보기`를 눌러 손으로 복사하면 됩니다.

### 곡 하나를 다음 찬양으로 정하기

**곡** 탭에서 곡 옆의 **`다음 찬양으로`**(곡 상세 화면에도 있습니다)를 누르면
찬양일과 연습 일정을 정하는 창이 뜹니다.

- 찬양일은 **아직 곡이 없는 다음 찬양주일**(기본 넷째 주일)이 미리 잡혀 있고, 바꿀 수 있습니다.
- 연습 일정은 `config`의 `연습기본패턴`으로 제안됩니다. 그 날 연습이 시트에 이미 있으면 그것을 보여줍니다.
- **적용**을 누르면 `services`·`rehearsals` 시트에 바로 들어가고, 홈 화면이 그 찬양으로 바뀝니다.
  같은 날 행이 이미 있으면 새 행을 만들지 않고 빈 곡 칸을 채웁니다. 이미 있는 연습은 다시 넣지 않습니다.

시트에 쓰려면 **편집 키**가 있어야 합니다. `config` 시트의 `앱편집키` 값이 키이고(기본 `selah`,
대소문자 무관), 앱에서 처음 적용할 때(또는 `…/#/settings`에서) 같은 키를 넣으면 그 폰에 남습니다.
키가 없거나 쓰기가 실패하면 같은 내용이 **붙여넣기 블록**으로 나오니 손으로 붙여넣으면 됩니다.

> 이 버튼은 **추가만** 합니다. 기존 곡이나 날짜를 지우거나 바꾸지 않으니, 고칠 것은 시트에서 고치세요.

### 다음 달 선곡하기

**선곡** 탭입니다. 이 화면의 진짜 목적은 공지 자동 생성이 아니라 **중복 선곡 방지**입니다.

곡을 고르는 자리에서 이런 것들이 함께 보입니다.

| 표시 | 왜 필요한가 |
|---|---|
| **마지막으로 부른 날** | 작년에 부른 곡을 기억 못 하고 다시 고르는 실수를 막습니다 |
| **붉은 배지** | 최근 12개월 안에 부른 곡입니다 |
| 파트 영상 없음 | 연습 자료를 직접 만들어야 한다는 것을 **고르는 시점에** 알려줍니다 |
| 난이도 | 한 달에 어려운 곡이 몰리지 않게 |
| 절기 힌트 | 10월이면 추수감사 곡을 먼저 보여줍니다 |

월을 고르면 **넷째 주일**이 찬양일로 잡히고, 연습 일정은 **둘째 주일 · 셋째 주일 · 셋째 주 수요일**로
제안됩니다. 이 규칙은 `config` 시트의 `찬양주일`과 `연습기본패턴`으로 바꿉니다.
다 고르면 **찬양일별 공지**가 나오고, **`시트에 반영`** 버튼이 곡이 있는 찬양일을 하나씩
`services`·`rehearsals`에 넣습니다(편집 키 필요, 규칙은 위 `다음 찬양으로`와 같습니다).
날짜별로 결과가 보이고, 실패한 날은 그 아래 **붙여넣기 블록**으로 넣으면 됩니다.

### 자료는 어디서 고치나

**편집은 구글 시트에서 합니다.** 앱이 시트에 쓰는 것은 위의 `다음 찬양으로`, 선곡 화면의
`시트에 반영`, 곡 상세의 파트 영상 `확인`과 빠진 파트 `영상 넣기`뿐입니다. `확인`은
`practice_links`의 `검증` 칸 하나만 켜고 끄고, 나머지는 행을 **추가**만 합니다.

편집자가 다섯 명 이내이고 모두 시트에 익숙하니, 앱에 범용 편집 화면을 만들어 로그인·권한·저장
실패까지 떠안을 이유가 없다고 봤습니다. 시트를 고치고 앱에서 `새로고침`을 누르면 바로 반영됩니다.

| 시트 | 무엇을 넣나 |
|---|---|
| `services` | 찬양일, 예배구분, 부른 곡, 파트별 인원, 찬양기록(실황) 영상 주소 |
| `rehearsals` | 연습 일정 (찬양일과 연결) |
| `practice_links` | 파트별 연습 영상 주소 |
| `songs` | 성가곡 후보 목록 |
| `books` | 보유 악보집 |
| `config` | 공지 형식, 교회 이름 등 설정 |

곡명은 **드롭다운으로만** 고르게 되어 있습니다. 손으로 치면 오타 하나에 앱이 곡을 못 찾습니다.

> **`config` 시트의 값이 언제나 이깁니다.** 앱이 안 바뀌면 먼저 이 시트를 확인하세요.

### 자동 수집한 자료는 확인 전까지 안 나갑니다

유튜브에서 자동으로 끌어온 영상 링크는 전부 `검증 = FALSE`로 들어옵니다.
이 상태에서는 **공지 텍스트에 포함되지 않고**, 앱에서도 흐리게 `미확인` 배지가 붙습니다.

사람이 재생해 보고 맞으면 체크를 켜야 대원들에게 나갑니다.
실제로 나무위키의 41집 표에 18집 링크가 잘못 들어가 있던 사례가 있어서 둔 장치입니다.

체크는 **곡 상세 화면에서** 합니다. 파트 영상마다 `확인` 버튼이 있어, 영상을 재생해 보고
누르면 편집 키로 시트의 `검증`이 켜집니다. 잘못 눌렀으면 `확인 취소`로 되돌립니다.
서가 전체를 한 번에 검수할 필요 없이, **공지할 곡만 그때그때** 확인하면 됩니다.

### 매주 이것 하나 — 이번 주 준비 상태

홈의 공지 아래 **이번 주 준비 상태**(또는 선곡 탭 맨 위, `…/#/ready`)를 열면 다음 찬양의
준비 상태가 한 장에 나옵니다.

| 항목 | 무엇을 보나 |
|---|---|
| 찬양일·곡 | 다음 찬양일이 시트에 있고 곡이 정해졌는지 |
| 파트 영상 | 곡마다 합창·소프라노·알토·테너·베이스 영상이 있고 **확인**됐는지 (확인 안 된 것은 공지에서 빠집니다) |
| 연습 일정 | 연습이 등록됐는지, 다음 연습은 언제인지 |
| 공지 | **이 기기에서** 공지를 복사했는지 (카톡 발송 여부까지는 알 수 없습니다) |
| 편집 키 | 기본값(selah) 그대로면 경고 |

곡마다 `확인·추가하기`를 누르면 곡 상세로 가서 영상을 확인하거나 빠진 영상을 넣을 수 있습니다.

### 주간 자동 점검 (메일)

**성가 아카이브 > 주간 자동 점검 켜기**를 한 번 누르면 매주 월요일 아침에 스크립트가 알아서

1. 채널의 새 영상을 받고 → 새 수록곡을 등록하고 → 파트 영상을 매칭하고
2. 삭제·비공개된 파트 영상을 찾아 `_깨진링크` 시트에 적고
3. 다음 찬양의 준비 상태(위 표와 같은 기준)를 정리해

`config`의 **`알림메일`** 주소로 보냅니다(여럿이면 쉼표). 결과는 `_주간점검` 시트에도 한 줄씩 남습니다.
`지금 실행`으로 바로 돌려 볼 수 있고, `끄기`로 멈춥니다.

> 처음 켤 때 구글이 **권한을 다시 묻습니다**(트리거·메일 발송). 승인하세요.
> `알림메일`은 개인 주소라 앱이 받는 JSON에는 나가지 않습니다.

### 누가 무엇을 바꿨나 — `_변경기록`

앱이 시트에 쓸 때마다(`다음 찬양으로`, `시트에 반영`, `확인`, `영상 넣기`) `_변경기록` 시트에
**시각 · 편집자 · 동작 · 내용 · 결과**가 남습니다. 편집 키가 틀린 시도도 남습니다.
편집자는 편집 키를 넣을 때 함께 적는 **내 이름**입니다(설정 화면에서도 바꿀 수 있습니다).

> **편집 키를 꼭 바꾸세요.** 기본값 `selah`는 이 README에 적혀 있어, 앱 주소를 아는 누구나
> 시트에 쓸 수 있습니다. 기본값 그대로면 앱의 편집 키 칸과 준비 상태 화면에 경고가 뜹니다.

### 앱에 안 보이는 파트 영상 채우기

유튜브에 분명히 있는데 앱에서 "없음"으로 보이는 파트가 있습니다(예: 36집 「이런 교회 되게 하소서」 알토).
채널 동기화가 재생목록을 따라가는데, 유튜브가 채널의 재생목록을 다 돌려주지 않기 때문입니다.

**한 곡만 급할 때 — 앱에서** (편집 키 필요)

1. 곡 상세의 **아직 없는 파트**에서 파트 버튼을 눌러 유튜브 검색을 엽니다.
2. 맞는 영상의 `공유` → `복사`로 주소를 얻습니다.
3. `찾은 영상을 이 곡에 넣기`를 펼쳐 파트를 고르고 주소를 붙여넣은 뒤 **영상 넣기**.
   사람이 골라 넣은 것이므로 **확인된 상태**로 들어가 바로 공지에 나갑니다.

**서가 전체를 한 번에 — 시트 메뉴에서**

1. **성가 아카이브 > 업로드 전체 동기화** — 채널이 올린 영상 전부를 받습니다(재생목록과 무관).
   한 번에 안 끝나면 "중단"이 뜨는데, **완료가 뜰 때까지 다시 누르면** 이어서 받습니다.
2. **곡명 정리 (파트 꼬리 떼기)** — 예전 규칙이 `이런 교회 되게 하소서 합창`처럼 곡명 끝에 파트를
   붙여 등록한 곡을 고칩니다. 바꿀 목록을 먼저 보여주고, 그 곡을 쓰던 `practice_links`·`services`
   칸도 함께 새 이름으로 바꿉니다.
3. **악보집 일괄 등록** → **영상 매칭**. 끝나면 **`_빠진파트`** 시트에 아직 비어 있는 곡·파트가
   유튜브 검색 주소와 함께 정리됩니다(부른 곡·예정곡이 맨 위).

> Apps Script를 갱신하고(`npm run gas:push` 또는 파일 붙여넣기) **새 버전으로 다시 배포**해야 앱의 `영상 넣기`가 동작합니다.

서가 탭의 책등에는 권마다 **영상 N%**(합창·S·A·T·B 다섯 파트 중 링크가 있는 비율)가 나오고,
권을 열면 파트별 막대와 빠진 파트가 보입니다.

## 처음 설치하기

이미 돌아가고 있다면 이 절은 건너뛰어도 됩니다.

### 1. 스프레드시트 준비

1. 새 구글 스프레드시트를 만들고, 파일 > 설정에서 **시간대를 (GMT-07:00) 로스앤젤레스**로 맞춥니다.
2. 확장 프로그램 > Apps Script를 열고 [`apps-script/`](apps-script/)의 파일을 올립니다.
   **권장: `clasp`** (아래 "Apps Script를 명령 하나로 올리기"). 손으로 붙여넣는다면
   `.gs` 파일 **전부와 `appsscript.json`**을 함께 최신으로 유지하세요 — 한 전역 스코프를 공유해서
   하나만 옛것이면 `ReferenceError`가 납니다.
   - `Code.gs` — 앱이 읽어갈 JSON, 앱의 쓰기 요청, `_변경기록`
   - `Setup.gs` — 시트 생성·드롭다운·자동 수식
   - `YouTubeSync.gs` — 유튜브 채널을 `yt_cache`로 복사
   - `Matching.gs` — 영상 제목 해석·매칭·`_빠진파트`·곡명 정리
   - `Books.gs` — 악보집·수록곡 등록
   - `Automation.gs` — 주간 자동 점검
3. 스프레드시트를 새로고침하면 상단에 **성가 아카이브** 메뉴가 생깁니다.
4. **성가 아카이브 > 시트 초기 생성**을 실행합니다.

> 스크립트를 고칠 때마다 **새 버전으로 다시 배포**해야 앱에 반영됩니다. 주소는 그대로입니다.

#### Apps Script를 명령 하나로 올리기 (clasp)

```bash
npm run gas:login                     # 처음 한 번, 구글 계정으로 로그인
cp .clasp.json.example .clasp.json    # scriptId에 Apps Script 프로젝트 ID를 넣는다
                                      #   (편집기 > 프로젝트 설정 > 스크립트 ID)
npm run gas:push                      # apps-script/ 전체를 올린다
GAS_DEPLOYMENT_ID=AKfy… npm run gas:deploy   # 올리고, 지금 웹앱 배포를 새 버전으로 (주소 그대로)
```

`.clasp.json`은 사람마다 다르므로 저장소에 올리지 않습니다.

### 2. 웹앱 배포

Apps Script 편집기에서 **배포 > 새 배포 > 웹 앱**:

| 항목 | 값 |
|---|---|
| 실행 주체 | **나** |
| 액세스 권한 | **모든 사용자** |

여기가 틀리면 앱이 JSON 대신 로그인 페이지를 받아 아무것도 안 보입니다.
시트 자체는 비공개로 남고, 대원들은 로그인 없이 앱만 봅니다.

발급된 `.../exec` 주소를 [`src/lib/api.ts`](src/lib/api.ts)의 `DEFAULT_ENDPOINT`에 넣습니다.

같은 배포가 `다음 찬양으로`·`시트에 반영`의 쓰기(POST)도 받습니다. 키는 `config` 시트의
`앱편집키` 행입니다(기본 `selah`, 대소문자 무관). `config`는 JSON으로 통째로 나가지만
**이 행만은 내보내기에서 뺍니다** — 앱을 여는 누구나 그 JSON을 볼 수 있기 때문입니다.

### 3. 앱 배포

1. Settings > General > Default branch가 `main`인지 확인합니다.
2. Settings > Pages > Source를 **GitHub Actions**로 바꿉니다.
3. `main`에 푸시하면 자동으로 배포됩니다.

> 저장소를 private으로 바꾸면 (무료 플랜에서) Pages가 꺼지고, 다시 public으로 돌려도
> **저절로 켜지지 않습니다.** 워크플로가 `enablement: true`로 스스로 켜도록 해 두었지만,
> 조직 정책으로 막히면 Settings > Pages에서 직접 켜야 합니다.

### 4. 자료 넣기

곡 목록 300곡을 다 채우는 것은 **시작 조건이 아닙니다.** 이 순서를 권합니다.

1. `books`에 보유 악보집만 먼저 — 이것만으로 앱이 돕니다.
2. **`services`에 최근 1~2년 찬양 기록** — 선곡 화면의 중복 경고가 여기서 나옵니다.
   기록이 없으면 그 기능이 몇 달간 비어 있습니다. 곡 목록보다 이게 먼저입니다.
3. 곡은 선곡할 때마다 한 곡씩 추가해도 됩니다.

2023~2026년 기록은 이미 옮겨 두었습니다 →
[`docs/BACKFILL-2023-2026.md`](docs/BACKFILL-2023-2026.md)

## 유튜브 채널에서 영상 끌어오기 (선택)

중앙아트TV 공식 채널에서 파트 영상과 수록곡 목록을 가져옵니다.

1. Apps Script 편집기 왼쪽 **[서비스] +** → **YouTube Data API v3** 추가 (식별자 `YouTube`).
   **API 키는 필요 없습니다** — 실행하는 사람의 구글 계정 권한으로 동작합니다.
2. **성가 아카이브 > 채널 동기화** — 채널 전체를 `yt_cache` 시트에 복사해 둡니다.
   `config`의 `유튜브채널핸들`(기본 `JandAArt`)로 채널을 찾습니다. `@JandAArt`나
   채널 주소를 통째로 넣어도 됩니다.

   > 채널을 찾는 순서는 **API 핸들 조회 → 채널 페이지에서 ID 읽기 → 사람에게 묻기**입니다.
   > 고급 서비스 버전에 따라 `forHandle`이 없을 수 있어 두 번째 경로를 둡니다.
   > 그래도 못 찾으면 `youtube.com/@JandAArt`에서 `Ctrl+U` → `Ctrl+F`로 `externalId`를
   > 찾아 `UC…` 24자를 넣으면 됩니다. 한 번 입력하면 저장됩니다.
   6분 제한에 걸리면 중단 지점을 남기고 멈추며, 다시 실행하면 **그 지점부터 이어서** 갑니다.
3. **성가 아카이브 > 제목 형식 확인** — 실제 영상 제목이 어떤 모양인지 눈으로 봅니다.
4. **성가 아카이브 > 악보집 일괄 등록** — `books`의 보유 권을 한 번에 처리합니다.
   캐시를 한 번만 읽고, 채널에 재생목록이 없는 권은 따로 모아 알려줍니다.
   (권을 하나만 넣으려면 `악보집 등록 (한 권)`)
5. **성가 아카이브 > 업로드 전체 동기화** — 재생목록에 안 잡힌 영상까지 채널 업로드 전체를 받습니다.
   (권장. 아래 "재생목록이 없다"는 문제를 통째로 피합니다.)
6. **성가 아카이브 > 영상 매칭** — 파트 영상이 `practice_links`에 검증 대기로 들어가고,
   아직 빈 파트는 `_빠진파트` 시트에 정리됩니다.

> **"채널에 재생목록이 없는 권"이라고 나와도 유튜브에 없는 것은 아닙니다.**
> `playlists.list`는 채널이 소유한 공개 재생목록만 돌려줘서, 유튜브에서 검색하면
> 멀쩡히 나오는 목록이 빠지기도 합니다(중앙성가 37·38집이 그랬습니다).
>
> `캐시 점검`을 누르면 채널 재생목록 전체가 `_재생목록` 시트에 나옵니다.
> 거기에도 없으면 유튜브에서 그 권을 찾아 주소를 복사해
> `재생목록 직접 추가`에 넣으세요. **여러 개를 줄바꿈으로 한 번에** 넣을 수 있고,
> `watch?v=…&list=PL…` 형태의 주소도 그대로 받습니다.
>
> 권마다 재생목록이 두 벌인 경우가 있습니다. **`[중앙아트] …집`(150~330개)에만
> 파트 영상이 있고**, `[합창 듣기] …집`(33~34개)은 합창 전곡 듣기용입니다.
> 파트가 비어 보이면 `[중앙아트]` 쪽 목록이 캐시에 있는지 확인하세요.

실제 채널 제목은 이런 형식입니다 (규칙은 여기에 맞춰져 있습니다).

```
[중앙아트] 중앙성가 52집｜31. 하나님은 영이시니 (입례송) – 소프라노
[중앙아트] 중앙성가 40집 32. 기도송 - 합창
[중앙아트] ‘하나님의 시선 9집’ 13. 어버이의 사랑 – 소프라노 MIDI
```

41집 이후는 같은 곡이 **MIDI와 실연 두 벌**로 올라옵니다. 연습에는 실연이 나으므로
같은 (곡, 파트)에 둘 다 있으면 실연을 고르고, 실연이 없을 때만 MIDI를 씁니다.

> 3~4단계가 핵심입니다. 채널 전체를 시트에 복사해 두었기 때문에,
> **매칭 규칙을 틀려도 다시 돌리는 데 비용이 들지 않습니다.**
> 곡마다 검색하는 방식이었다면 규칙을 고칠 때마다 할당량을 다시 태웠을 겁니다.

`yt_cache`를 통째로 다시 받고 싶을 때만 **캐시 비우기**를 씁니다.
매칭 규칙만 고칠 때는 지우지 마세요.

## 기술 구성

### 전체 구조

```
구글 스프레드시트  (자료가 실제로 사는 곳)
   │  시트 7장 + 연도별 보기 탭
   │
   ▼
Apps Script 웹앱  (doGet → JSON, 읽기 전용)
   │  주소 하나로 6장을 한 번에 내려줌
   │
   ▼
브라우저          (React 앱)
   │  받은 내용을 localStorage에 저장해 두고,
   │  네트워크가 끊기면 마지막 내용을 대신 보여줌
   ▼
GitHub Pages      (정적 호스팅 · 서버 비용 0)
```

### 스택

| 층 | 사용 | 왜 |
|---|---|---|
| 자료 저장 | Google Sheets | 편집자들이 이미 쓸 줄 안다. 버전 기록도 남는다 |
| 서버 | Apps Script `doGet` | 시트를 JSON으로 내주는 것만. 서버를 따로 둘 이유가 없다 |
| 화면 | React 18 + TypeScript | |
| 빌드 | Vite 5 | |
| 스타일 | Tailwind CSS 3 | |
| 라우팅 | React Router (**HashRouter**) | Pages에는 서버 리라이트가 없어 일반 라우터면 새로고침 시 404가 난다 |
| 테스트 | Vitest | 공지 형식 등 되돌아가면 안 되는 규칙을 고정 |
| 배포 | GitHub Actions → Pages | `main`에 푸시하면 자동 |

### 폴더

```
src/
  lib/                자료를 다루는 부분 (화면과 분리)
    types.ts          자료 모양 정의
    schema.ts         시트 JSON → 앱이 쓰는 형태로 변환
    notice.ts         공지 텍스트 생성          ← 형식이 테스트로 고정됨
    planner.ts        월간 선곡, 중복 판정, 필터
    paste.ts          시트에 붙여넣을 블록 만들기
    write.ts          시트 쓰기 요청 — 찬양일 추가(applyPlan), 파트 영상 검증(verifyLink)·추가(addLink)
    derive.ts         시트를 가로지르는 조회 (부른 이력, 파트별 링크)
    youtube.ts        유튜브 주소 정규화
    api.ts            자료 받아오기 + 오프라인 캐시
    date.ts           날짜·시각 표기
    color.ts          표지색 위에 올릴 글자색 계산
  components/         여러 화면이 함께 쓰는 조각
  pages/              홈 · 아카이브 · 곡 · 서가 · 곡상세 · 선곡 (+ 탭에 없는 설정)

public/               홈 화면 아이콘과 웹 매니페스트
fixtures/             로컬에서 화면 볼 때 쓰는 표본 응답 (배포에는 안 들어감)
apps-script/          구글 시트에 붙여넣는 스크립트
scripts/              시트 응답 점검 도구, 아이콘 렌더
docs/                 기획서, 판단 기록, 붙여넣기 블록
```

### 설계에서 지키는 것

- **열 위치가 아니라 헤더 이름으로 읽습니다.** 다섯 명이 동시에 만지면 열 삽입·삭제가
  반드시 일어납니다. 열이 움직여도 앱이 깨지지 않습니다.
- **한 행의 오타로 앱 전체가 멈추지 않습니다.** 읽지 못한 값은 빈 값으로 떨어집니다.
  주일 아침에 화면이 하얗게 뜨는 것이 최악입니다.
- **오프라인 내성.** 마지막으로 받은 내용을 저장해 두고, 네트워크가 실패하면 그것을 보여줍니다.
  교회 와이파이가 불안정한 날을 위한 것입니다.
- **자동 수집한 자료는 초안이지 사실이 아닙니다.** 사람이 확인해야 공지에 나갑니다.
- **앱의 쓰기는 좁습니다.** `다음 찬양으로`와 `시트에 반영`은 행을 붙이거나 빈 칸을 채울 뿐,
  있는 값을 지우거나 바꾸지 않습니다. 파트 영상 `확인`은 `검증` 체크 하나만 켜고 끕니다. 되돌리기는 시트의 버전 기록으로 합니다.

### 개발

```bash
npm install
npm run dev      # 개발 서버
npm test         # 테스트 (공지 형식·주소 정규화·중복 판정·설정 기본값)
npm run lint     # 타입 검사
npm run build    # 배포용 빌드
npm run icons    # public/icon.svg를 고쳤을 때 PNG 다시 만들기
npm run og       # (빌드 뒤) dist/index.html의 카톡 미리보기를 다음 찬양으로 — 배포가 자동으로 함
```

### 자동으로 도는 것 (GitHub Actions)

| 워크플로 | 언제 | 무엇을 |
|---|---|---|
| `ci.yml` | PR·푸시 | 타입 검사 · 테스트 · 빌드 |
| `deploy.yml` | `main` 푸시 + **매일 아침** | 배포. 매일 다시 배포해 카톡 링크 미리보기를 그날의 다음 찬양(날짜·곡·다음 연습)으로 바꿉니다 |
| `verify-data.yml` | 매주 월요일 | 실제 시트 응답을 앱과 같은 코드로 점검(`npm run verify -- … --strict`). 곡명 참조 오류·버려진 행·주소 오류가 있으면 실패하고, GitHub이 관리자에게 메일을 보냅니다 |

> 카톡은 미리보기를 한동안 캐시합니다. 이미 공유된 링크의 미리보기는 바로 바뀌지 않을 수 있습니다.

로컬에서 화면을 볼 때는 `fixtures/sample-payload.json`을 정적으로 띄우고,
브라우저 콘솔에서 `localStorage.setItem('kpccw.archive.endpoint', '<그 주소>')` 하면 됩니다.

시트가 앱에 제대로 도착했는지 확인하려면:

```bash
npm run verify -- https://script.google.com/macros/s/.../exec
```

시트 대비 버려진 행, 곡명 참조 오류, 주소 오류, 그리고 실제로 만들어질 공지를
앱과 **같은 코드로** 출력합니다.

교회 홈페이지에서 실황영상 주소를 모아 오려면 — 게시판의 `num`은 다른 영상들과
섞여 올라가며 붙은 일련번호라 계산할 수 없어, 범위를 훑어 제목으로 맞춰야 합니다.

- **브라우저에서** (설치 불필요): 게시판을 연 뒤 `F12` → Console에
  [`scripts/find-recordings-console.js`](scripts/find-recordings-console.js)를 붙여넣습니다.
  결과가 클립보드에 복사됩니다.
- **내 PC에서**: `node scripts/find-recordings.mjs --from 150 --to 390`

둘 다 **KPCCW 성가대** 항목만 골라 `services` 시트의 `기록영상URL`에 넣을 형태로 출력합니다.

> `notice.ts`의 출력은 실제 카톡 공지 원문으로 테스트에 고정되어 있습니다.
> 형식을 "개선"하는 변경은 전부 회귀입니다. 바꾸려면 `config` 시트를 통해야 합니다.
