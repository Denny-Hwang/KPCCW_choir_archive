# 구현 판단 기록

기획서(v5)를 코드로 옮기며 결정해야 했던 것들. 기획서에 답이 없던 자리와,
답이 있었지만 구현 중에 반대 근거가 나온 자리를 나눠 적는다.

## 1. 기획서에 답이 없어 판단한 것

### 1.1 공지 텍스트의 빈 줄 — 기본은 **없음**

§7의 예시 블록에는 제목·연습 일정·파트 블록 사이에 빈 줄이 없다.
"글자 단위로 재현"이 요구사항이므로 예시를 문자 그대로 따랐다.

다만 실제 카톡 공지에는 빈 줄이 있었을 가능성이 있다(마크다운 코드 블록으로 옮기며
사라졌을 수 있다). 그래서 `config`에 `공지_빈줄구분` 키를 두었다. 기본값 `FALSE`가
기획서 그대로이고, `TRUE`로 바꾸면 구역 사이에 빈 줄이 들어간다.

> **확인이 필요하다.** 실제 공지 원문과 대조해 기본값을 확정할 것.
> 코드 수정 없이 `config` 한 칸으로 바뀐다.

### 1.2 제목 형식의 치환자 확장

§7 기본값은 `{M}월 {D}일 주일 찬양`인데, §7.1의 다곡 예시는 `12월 25일 성탄 찬양`이다.
"주일"이 "성탄"으로 바뀌어 있다. 형식 문자열이 고정이면 이 제목이 나올 수 없다.

`{구분}`(=`예배구분` 열)과 `{YYYY}` 치환자를 추가했다. 기본값은 그대로라 기존 동작은
바뀌지 않고, 성탄·부활 같은 날만 `config`에서 `{M}월 {D}일 {구분} 찬양`으로 바꾸면 된다.

### 1.3 다곡 공지의 곡명은 `제목`

§7.1의 예시가 `1. (곡명)`이라 `표시명`(`주만이 내 반석 (중47-03)`)인지 `제목`인지
불분명했다. 공지는 대원이 읽는 글이고 곡코드는 대원에게 의미가 없으므로 `제목`을 쓴다.
`songs`에 없는 곡명이 `services`에 들어 있으면 표시명 끝의 `(...)`를 떼어 쓴다.

### 1.4 같은 파트에 링크가 여러 개일 때

기획서에 규정이 없다. 공지에는 **파트당 하나만** 넣는다 — 링크가 두 줄 나오면
대원이 무엇을 봐야 할지 알 수 없다. 검증된 것 중 첫 번째를 쓰고, 홈 화면의 파트 버튼에는
`+N` 배지로 나머지가 있음을 표시한다.

### 1.5 `hasParts`는 반주를 세지 않는다

선곡 화면의 "파트 영상 없음" 경고는 *파트 연습 자료를 직접 만들어야 하는가*를 묻는 것이다.
반주 영상만 있는 곡은 파트 연습 자료가 있다고 볼 수 없으므로 경고를 띄운다.

### 1.6 중복 판정의 기준일

선곡 대상 월의 1일을 기준으로 삼는다. 오늘 날짜를 쓰면 내년 3월을 계획할 때
"9개월 전에 불렀음"이 나오는데, 정작 그 곡을 부를 시점에는 21개월 전이 된다.
계획하는 시점이 아니라 **부르는 시점** 기준이어야 경고가 맞는다.

기준일 이후에 이미 `services`에 예정으로 들어간 찬양은 "부른 이력"으로 세지 않는다.

### 1.7 앱은 시트에 쓰지 않는다 (§12.2는 구현하지 않음)

기획서가 §12.2를 P4로 미뤘고, "필요가 확인되면"이라는 조건을 달았다.
붙여넣기 블록(§12.1)이 폴백이 아니라 **유일한 경로**로 먼저 서 봐야 그 필요가 확인된다.
그래서 쓰기 엔드포인트도, 공유 키 입력 칸도 만들지 않았다.

## 2. 구현 중에 드러난 문제

### 2.1 Apps Script의 Date 직렬화와 시간대 — **서버에서 해결, 설정으로 노출**

`getValues()`가 준 `Date`를 `JSON.stringify`하면 UTC ISO가 된다. 시트 시간대가 UTC+
지역이면 자정이 전날로 넘어가 클라이언트가 앞 10자를 자를 때 날짜가 하루 밀리고,
PDT/PST처럼 UTC- 지역이면 날짜는 밀리지 않지만 시각이 어긋난다.

`Code.gs`의 `normalizeCell_`이 시트 시간대로 포맷한 문자열을 내려주는 것으로 해결했다.
클라이언트(`schema.ts`)도 시각이 붙은 ISO를 받으면 시간대로 환산하는 2차 방어를 둔다.

**기준 시간대는 `America/Los_Angeles`(PDT/PST)다.** 처음에는 한국 교회로 짐작해
`Asia/Seoul`로 잡았는데, 실제 운영이 미국 태평양 시간이라는 확인을 받고 바꿨다.
같은 실수가 반복되지 않도록 하드코딩 대신 `config` 시트의 `시간대` 키로 뺐고,
알 수 없는 IANA 이름이 들어오면 기본값으로 되돌린다.

이 지역은 한국과 달리 **썸머타임이 있다.** 고정 오프셋으로 계산하면 3월과 11월에
어긋나므로, 오프셋이 아니라 IANA 시간대 규칙으로 환산한다. 테스트가 PDT·PST 양쪽을 덮는다.

시각 전용 셀은 시트 에폭(1899-12-30) 기준으로 내려오는데, 그 시절에는 표준시가 아직
지금 형태가 아니었다(로스앤젤레스는 LMT `-07:52:58`). 같은 시간대 규칙으로 되돌려야만
값이 맞으므로, 여기서도 고정 오프셋을 쓰지 않는다.

### 2.2 `songs`의 자동 생성 열에 빈 값을 쓰면 수식이 깨진다

`곡코드`·`표시명`은 2행의 ARRAYFORMULA가 아래로 채운다(§4.2).
악보집 등록 스크립트가 행 전체를 `setValues`하면 그 두 열에 `''`가 들어가면서
배열 수식이 `#REF!`로 죽는다.

`appendSongs_`가 수식 열을 건너뛰고 **연속 구간 단위로만** 쓰도록 고쳤다.

### 2.3 나무위키 링크 오류는 채널 미러링으로도 완전히 사라지지 않는다

§9.3이 지적한 41집/18집 링크 혼동은 공식 채널을 1순위로 올리면 사라진다.
그러나 **제목 매칭이 틀릴 가능성**은 남는다. 그래서 매칭 결과는 전부 `검증=FALSE`로
들어가고, 미검증 링크는 `buildNotice`에서 제외된다. 이 규칙은 테스트로 고정되어 있다.

### 2.4 채널 미러링을 고급 서비스로 바꿨다

처음에는 `UrlFetchApp` + 스크립트 속성의 `YOUTUBE_API_KEY`로 구현했다.
Apps Script의 **YouTube 고급 서비스**를 쓰면 실행하는 사람의 OAuth로 동작해
**키를 만들고 보관하는 단계가 통째로 사라진다.** 운영이 단순해지므로 교체했다.

함께 고친 것:

- **중복 판정을 `videoId`에서 `videoId|playlistId` 조합으로.** 같은 영상이
  '중앙성가 41집'과 '음원 모음'에 모두 들어 있을 수 있는데, `videoId`만으로 걸러내면
  집 번호를 알려주는 쪽 행이 사라져 매칭이 실패한다.
- **6분 제한 대응(재개).** 중단 지점을 재생목록 인덱스**와 페이지 토큰**으로 남긴다.
  인덱스만 남기면 두 가지가 깨진다. (1) 중단된 재생목록을 완료 처리해 뒷부분을 영영
  건너뛴다 — 알림은 정상 완료로 뜬다. (2) 그걸 고쳐 그 재생목록을 다시 돌리게 해도,
  0쪽부터 재탐색하므로 재생목록 하나의 페이지 수가 한 번의 실행 예산을 넘으면
  영원히 끝에 닿지 못한다. 토큰까지 저장해야 둘 다 없어진다.
- 토큰이 어느 재생목록의 것인지(`RESUME_PLAYLIST_ID`)도 함께 확인한다.
  채널의 재생목록 순서가 실행 사이에 바뀔 수 있기 때문이다.

### 2.5 `onOpen`은 프로젝트에 하나만 둔다

Apps Script의 `.gs` 파일들은 **하나의 전역 스코프**를 공유한다. 같은 이름의 함수가
둘이면 오류 없이 나중 파일이 이긴다. `onOpen`이 겹치면 메뉴 하나가 통째로 사라지는데,
아무 경고도 나오지 않아 원인을 찾기 어렵다. 메뉴는 `Code.gs`의 `onOpen` 한 곳에만 있다.

## 3. 남은 미결정 사항 (§11)

### 앱을 쓰기 시작하면 자연히 답이 나오는 것

- [ ] **중앙아트TV 영상 제목 형식** — `채널 동기화` 1회 실행 후 `yt_cache`를 눈으로 확인.
      `parseVideoTitle_`은 곡번호·파트 표기의 흔한 형태를 잠정 처리하고 있으며,
      규칙을 고쳐 재실행해도 API 할당량은 들지 않는다.
- [ ] 보유 11권 중 채널에 집별 재생목록이 있는 권의 범위 — 같은 실행에서 확인된다.
- [ ] 43집·47집의 나무위키 수록곡 표 존재 여부.
- [ ] `pop1` / `pop3` 파일명의 의미.

### 사람에게 물어야 하는 것

- [ ] **공지 빈 줄** (위 1.1) — 실제 카톡 공지 원문과 대조.
- [ ] **과거 기록 백필 범위** — 기획서가 "우선순위 높음"으로 짚은 그대로다.
      `services`에 과거 기록이 없으면 선곡 화면의 중복 경고가 작동하지 않아
      핵심 가치가 몇 달간 비어 있다. 기존 카톡 공지는 포맷이 일정하므로 파싱 가능.
- [ ] 공지를 주별로 보내는 것이 맞는지 (현재 설계 전제). 월 단위 통합 공지도 쓰는지.
      → 선곡 화면은 둘 다 생성한다: 찬양일별 공지 + 월 전체 요약.
- [ ] 예배구분 값 목록 (주일 1부/2부 구분, 특별예배 명칭 체계).
      → 현재는 자유 입력. 값이 확정되면 `Setup.gs`에 드롭다운을 추가하면 된다.
- [ ] `절기` 태그 목록을 교회 절기력에 맞게 확정.
      → 현재 `Setup.gs`의 `SEASONS`에 7개.
- [ ] 각 권의 표지색 실물 HEX — 예시 데이터에는 사진 색감 기준 근사값이 들어 있다.
- [ ] 시트 시간대가 `America/Los_Angeles`로 맞춰져 있는지 (파일 > 설정).
      `config`의 `시간대` 값과 어긋나면 날짜가 하루 밀릴 수 있다.
- [ ] 연습 기본 패턴이 매달 동일한지.
- [ ] 중앙성가 17집 표지의 작은 글씨.

### 다음 작업으로 남긴 것

- [ ] **기록영상이 유튜브가 아닌 경우** (구글 드라이브 등) — 현재는 링크를 그대로 열고
      설정 화면의 "주소 인식 실패"에 집계된다. 깨진 링크와 구분되지 않는 것이 아쉽다.
- [ ] **카톡 공유 시 미리보기(OG 태그)** — `index.html`에 정적 OG 태그가 있다.
      찬양일별로 다른 미리보기를 주려면 정적 호스팅으로는 부족하다.
- [ ] **채널 영상이 비공개/삭제될 때의 링크 깨짐 감지** — `videos.list`로 캐시의
      videoId를 주기적으로 확인하면 된다(50개당 1 unit). 아직 만들지 않았다.
- [ ] 통계 화면 (§6.6, P4).
- [ ] PWA / 오프라인 셸 — 현재는 localStorage 캐시까지만.
- [ ] 이동축일(사순·부활) 계산 — 기획서대로 월→절기 힌트 매핑으로만 처리 중.
